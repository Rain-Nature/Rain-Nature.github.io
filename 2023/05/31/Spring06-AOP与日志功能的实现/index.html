1. SpringAOP的入门

(1) 初识AOP

​ AOP（Aspect Oriented Programming）：面向切面编程，其是在OOP（Object Oriented Programming：面向对象编程）基础上新的编程思想

​ 面向切面编程：指在程序运行期间，将某段代码动态的切入到指定位置进行运行的这种编程方式

实质业务场景

​ 1.日志功能的实现

​ 2.AOP做事务控制

底层技术逻辑

​ 在java.lang.reflect.Proxy中有一个方法static Object newProxyInstance (ClassLoader loader, Class<?>[] interfaces, InvocationHandler h)，其可以为目标对象创建一个代理对象，该代理对象可以执行目标对象中定义的方法，同时你可以在代理对象执行时在前后增加日志功能

  • ClassLoader loader：被代理对象的类加载器（xxx.getClass().getClassLoader()）

  • Class<?>[] interfaces：被代理对象的所有接口（xxx.getClass().getInterfaces()）

  • InvocationHandler h：方法执行器：定义所有方法调用时要执行的逻辑，帮我们目标对象执行目标方法，定义方式如下：

    //方法执行器。帮我们目标对象执行目标方法
InvocationHandler h = new InvocationHandler() {
	/**
	 * Object proxy：代理对象；给jdk使用，任何时候都不要动这个对象
	 * Method method：当前将要执行的目标对象的方法
	 * Object[] args：这个方法调用时外界传入的参数值
	 */
	@Override
	public Object invoke(Object proxy, Method method, Object[] args)
			throws Throwable {
		return null;
	}
};

(2) AOP实现：在计算器运行计算方法的时候进行日志记录（JDK Proxy）

需求分析

​ 日志记录：系统的辅助功能

​ 业务逻辑：加减乘除方法（核心功能）

​ 若直接将日志逻辑编写在方法内部；不推荐，修改维护麻烦【耦合】。可以使用动态代理将日志代码动态的在目标方法执行前后先进行执行【解耦合】

​ 我们希望的是日志模块在核心功能运行期间，自己动态的加上

//LogUtils.java：日志业务实现
public class LogUtils {
	
	public static void logStart(Method method,Object... args){
		System.out.println("【"+method.getName()+"】方法开始执行，用的参数列表【"+Arrays.asList(args)+"】");
	}
	
	public static void logReturn(Method method,Object result){
		System.out.println("【"+method.getName()+"】方法正常执行完成，计算结果是："+result);
	}

	public static void logException(Method method, Exception e) {
		System.out.println("【"+method.getName()+"】方法执行出现异常了，异常信息是："+e.getCause()+"；这个异常已经通知测试小组进行排查");
	}

	public static void logEnd(Method method) {
		System.out.println("【"+method.getName()+"】方法最终结束了");
	}

}

public class AOPTest {

	 * 有了动态代理，日志记录可以做的非常强大；而且与业务逻辑解耦

		calculator.div(2, 1);
		
		System.out.println("[==========]");

		System.out.println(Arrays.asList(proxy.getClass().getInterfaces()));
        //用代理对象执行业务逻辑，实质上是进入invoke()中进行执行
		proxy.add(2, 1);
		proxy.div(2, 0);
	}

//CalculatorProxy.java
/**
 * 帮Calculator.java生成代理对象的类
 */
public class CalculatorProxy {

	/**
	 * 为传入的参数对象创建一个动态代理对象
	 * @param calculator
	 * @return
	 */
    //final Calculator calculator：因为要在内部类中使用calculator所以要修饰符final
	public static Calculator getProxy(final Calculator calculator) {		
		//方法执行器。帮我们目标对象执行目标方法
		InvocationHandler h = new InvocationHandler() {
			/**
			 * Object proxy：代理对象；给jdk使用，任何时候都不要动这个对象
			 * Method method：当前将要执行的目标对象的方法
			 * Object[] args：这个方法调用时外界传入的参数值
			 */
			@Override
			public Object invoke(Object proxy, Method method, Object[] args)
					throws Throwable {
				//利用反射执行目标方法
				//目标方法执行后的返回值
				Object result = null;
				try {
                    //日志
					LogUtils.logStart(method, args);
                    //方法执行
					result = method.invoke(calculator, args);
                    //日志
					LogUtils.logReturn(method, result);
				} catch (Exception e) {
					LogUtils.logException(method,e);
				}finally{
					LogUtils.logEnd(method);
					
				}
				
				//返回值必须返回出去外界才能拿到真正执行后的返回值
				return result;
			}
		};
        //定义代理类要实现哪些接口
		Class<?>[] interfaces = calculator.getClass().getInterfaces();
        //定义代理类使用哪个类加载器
		ClassLoader loader = calculator.getClass().getClassLoader();
		
		//Proxy为目标对象创建代理对象；
		Object proxy = Proxy.newProxyInstance(loader, interfaces, h);
		return (Calculator) proxy;
	}
}

(3) JDK Proxy的问题与Spring Proxy（CGLIB）

JDK Proxy的问题

​ 1.写起来难

​ 2.jdk默认的动态代理，如果目标对象没有实现任何接口，是无法为他创建代理对象的

Spring Proxy（Spring 实现AOP功能底层就是动态代理）

​ 1.可以利用Spring一句代码都不写的去创建动态代理， 实现简单，而且没有强制要求目标对象必须实现接口

2. AOP专业术语

图示

​ 注意：要记增强的四个时间段

AOP专业术语定义
  • Target(目标对象)：代理的目标对象
  • Proxy(代理)：代理对象
  • Joinpoint(连接点)：程序执行过程中可以插入增强逻辑的位置
  • Pointcut(切入点)**：连接点真正被增强了叫做切入点**
  • **Advice(通知/增强)**：在匹配到的 Joinpoint 上执行的额外逻辑代码
  • **Aspect(切面)**：是切入点和通知(增强)的结合（完整的逻辑-核心逻辑+增强逻辑）
  • Weaving(织入)：编写切面逻辑的动词

3. Spring的AOP功能（CGLIB）

(1) 使用Spring的AOP功能改写在计算器运行计算方法的时候进行日志记录

​ 使用Spring的AOP功能不需要再写切面类（CalculatorProxy.java）

Spring的AOP功能的使用步骤

​ 1.导包（spring-aop / aspectj）

​ 2.将目标类和切面类（封装了通知方法（在目标方法执行前后执行的方法））加入到ioc容器中

​ 3.使用注解@Aspect告诉Spring到底哪个是切面类

​ 4.在AOP配置类或springboot启动类上使用注解@EnableAspectJAutoProxy开启基于注解的AOP功能

​ 5.使用5种通知注解告诉Spring，切面类里面的每一个方法，都是何时运行

​ 6.使用切入点表达式，指定切面类中的方法何地运行

切面类中的五种通知注解及运行顺序

​ 注意1-@Around：特殊，等价上面四个

​ 注意2-切入点表达式：execution(访问权限符 返回值类型 方法签名(全限定名))，用于告知spring要切入那个方法

通知类型 执行时机 说明
@Before(“切入点表达式”) 在目标方法之前运行 前置通知
@After(“切入点表达式”) 在目标方法结束之后 后置通知
@AfterReturning(“切入点表达式”) 在目标方法正常返回之后 返回通知
@AfterThrowing(“切入点表达式”) 在目标方法抛出异常之后运行 异常通知
@Around(“切入点表达式”) 环绕（方法前后都可控制） 环绕通知

(3) 细节二：切入点表达式的写法

切入点表达式语法

​ 固定格式：execution(访问权限符 返回值类型 方法签名(全限定名))

通配符

*：

​ 1）匹配一个或者多个字符：execution(public int com.atguigu.impl.MyMath*r.*(int, int))

​ 2）匹配任意一个参数：第一个是int类型，第二个参数任意类型；（匹配两个参数）

​ execution(public int com.atguigu.impl.MyMath*.(int, \))

​ 3）只能匹配一层路径：execution(public int com.atguigu.*.MyMath*r.*(int, int))

​ 4）权限位置*不能写；只能写public【也可不写，默认也是public】

..：

​ 1）匹配任意多个参数，任意类型参数：execution(public int com.atguigu.impl.MyMath*r.*(..))

​ 2）匹配任意多层路径：execution(public int com.atguigu..MyMath*.*(..))

记住两种；

​ 最精确的：execution(public int com.atguigu.impl.MyMathCalculator.add(int,int))

​ 最模糊的：execution(* .\(..))：知道就行，千万别写；

&&、||、!：

&&：我们要切入的位置满足这两个表达式

​ execution(public int com.atguigu..MyMath*.(..))&&execution(\ .\(int,int))

||:满足任意一个表达式即可

​ execution(public int com.atguigu..MyMath*.(..))||execution(\ .\(int,int))

!：只要不是这个位置都切入

​ !execution(public int com.atguigu..MyMath*.*(..))

(4) 细节三：通知方法的执行顺序

通知方法对应JDK Proxy的位置

try{
@Before
method.invoke(obj,args);
@AfterReturning
}catch(e){
@AfterThrowing
}finally{
@After
}

通知方法的执行顺序

​ 注意：@Before 在方法执行前一定执行 ，@After 类似 finally，无论方法是否异常都会执行

正常返回时执行顺序：
@Before（前置通知）====> @After（后置通知）===> @AfterReturning（正常返回）

异常时执行执行顺序：
@Before（前置通知）====> @After（后置通知）===> @AfterThrowing（方法异常）

(5) JoinPoint：在通知方法中获取目标方法的详细信息

​ 在之前的切面类-LogUtils.java–简单版中，并没有获得目标方法的任何信息，可以使用JoinPoint传递参数等详细信息（不包含返回值和异常），赋予通知方法更强大的功能

JoinPoint的使用语法

1）只需要为通知方法的参数列表上写一个参数：JoinPoint joinPoint

​ JoinPoint joinPoint：封装了当前目标方法的详细信息

样例：修改原LogUtils.java中的logStart()方法
//LogUtils.java
@Before("execution(public int com.atguigu.impl.MyMathCalculator.*(..))")
public static void logStart(JoinPoint joinPoint){
	//获取到目标方法运行是使用的参数
	Object[] args = joinPoint.getArgs();
	//获取到方法签名
	Signature signature = joinPoint.getSignature();
	String name = signature.getName();
	System.out.println("【"+name+"】方法开始执行，用的参数列表【"+Arrays.asList(args)+"】");
}

(6) 通知方法对返回值和异常的获取

通知方法对返回值和异常的获取语法

1）对于返回值，只需要在参数列表中用一个Object result作为参数，并在通知注解@AfterReturning中用returning=”result”告知Spring，是用result来接收返回值即可

2）对于异常，只需要在参数列表中用一个Exception exception作为参数，并在通知注解@AfterThrowing中用throwing=“exception”告知Spring，是用exception来接收异常即可

​ 注意：Exception exception是指定通知方法可以接收哪些异常，如果写小了，例如具体的空指针异常，那发生其他异常（如数学异常）时，会接收不到

样例1：修改原LogUtils.java中的logReturn()方法
//LogUtils.java
@AfterReturning(value="execution(public int com.atguigu..MyMath*.*(..))",returning="result")
public static void logReturn(JoinPoint joinPoint,Object result){
	Signature signature = joinPoint.getSignature();
	String name = signature.getName();
	System.out.println("【"+name+"】方法正常执行完成，计算结果是："+result);
}
样例2：修改原LogUtils.java中的logException()方法
//LogUtils.java
@AfterThrowing(value="execution(public int com.atguigu.impl.MyMathCalculator.*(..))",throwing="exception")
public static void logException(JoinPoint joinPoint,Exception exception) {
	System.out.println("【"+joinPoint.getSignature().getName()+"】方法执行出现异常了，异常信息是【"+exception+"】：；这个异常已经通知测试小组进行排查");
}

(7) 细节四：通知方法参数列表的注意事项

​ 所有通知方法都是Spring帮忙调用的，本身你不会去调用，所以通知方法的参数列表（即所有参数），Spring必须要全都认识，如果Spring不认识，运行该通知方法会报错

(8) 抽取可重用的切入点表达式

抽取可重用的切入点表达式步骤

​ 1.随便声明一个没有实现的返回void的空方法（liu()）

​ 2.在方法上标注@Pointcut注解，并在里面写需要的切入点表达式

​ 3.在需要切入点表达式的地方，使用liu()代替

样例：抽取修改后LogUtils.java中的logException()方法
//LogUtils.java
@Pointcut("execution(public int com.atguigu.impl.MyMathCalculator.*(..))")
public void liu(){}

//此时所有的通知方法都可以使用这个抽取的切入点表达式
@AfterThrowing(value="liu()",throwing="exception")
public static void logException(JoinPoint joinPoint,Exception exception) {
	System.out.println("【"+joinPoint.getSignature().getName()+"】方法执行出现异常了，异常信息是【"+exception+"】：；这个异常已经通知测试小组进行排查");
}

(9) 环绕通知@Around（实际开发用的很少）

​ 环绕通知是上述四个通知的四合一。实际上，标注@Around的方法，需要在方法中手动将动态代理的try-catch块的四个位置实现一遍

注意：环绕通知中有一个参数：ProceedingJoinPoint pjp

​ ProceedingJoinPoint相比之前的JoinPoint多了一个核心能力：proceed()–手动触发目标方法执行

​ 底层关系：public interface ProceedingJoinPoint extends JoinPoint

样例：@Around的使用

​ 注意：我们可以操控最终的返回值来实现通过通知方法操作目标方法的返回结果

//LogUtils.java
@Around("liu()")
public Object myAround(ProceedingJoinPoint pjp) throws Throwable{
	
	Object[] args = pjp.getArgs();
	//获取目标方法名
	String name = pjp.getSignature().getName();
	
	Object proceed = null;
	try {
		//@Before
		System.out.println("【环绕前置通知】【"+name+"方法开始】");
		//就是利用反射调用目标方法，就是method.invoke(obj,args)，返回值用proceed接收
		proceed = pjp.proceed(args);
		//@AfterReturing
		System.out.println("【环绕返回通知】【"+name+"方法返回，返回值"+proceed+"】");
	} catch (Exception e) {
		//@AfterThrowing
		System.out.println("【环绕异常通知】【"+name+"】方法出现异常，异常信息："+e);
		//为了让外界能知道这个异常，这个异常一定抛出去
		throw new RuntimeException(e);
	} finally{
		//@After
		System.out.println("【环绕后置通知】【"+name+"】方法结束");
	}
	
	//反射调用后的返回值一定要返回出去，当然对于返回值是可操作的（例如整型数据*2等）
	return proceed;
}

(10) 细节五：单切面同一目标方法环绕通知和普通通知的执行顺序

环绕通知优先于普通通知执行

执行顺序：简记为：【普】—【环】—【普】

​ （环绕前置—普通前置）—-目标方法执行(环绕在执行)—-环绕正常返回/出现异常—–环绕后置—-普通后置—普通返回或者异常

注意1：前置通知的顺序无所谓，谁在前都行，方法执行后，严格按上述顺序执行

注意2：对于异常，如果编写逻辑时环绕通知没有抛出异常，那么普通通知会正常执行（因为检测不到异常）

(11) 细节六：多切面切入同一方法时通知执行顺序

​ 多切面切入时，原则上应该指定（单切面中四个通知方法的）优先级，如果没有指定，Spring将按类名的首字母排序给与执行时的优先级

设定通知类优先级

​ 在通知类的类名上使用@Order可以指定通知类的优先级，数字越小优先级越高

//LogUtils.java
@Aspect
@Component
@Order(1)//使用Order改变切面顺序；数值越小优先级越高
public class LogUtils {
	//...
}
