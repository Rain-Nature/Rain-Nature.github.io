2. Dto和Vo的区别

​ dto是封装输入参数（客户端 → 服务端，或服务 → 服务），vo是封装输出结果（服务端 → 客户端）

概念 全称 用途 典型使用场景
DTO Data Transfer Object（数据传输对象） 常见于 Service → Controller 之间，或者 服务A → 服务B 微服务之间的 RPC 调用、接口传参
VO View Object（视图对象） 常见于 Controller → 前端 Controller 返回给前端的 JSON、页面渲染数据

​ 在微服务、跨系统调用中 → DTO 必不可少，保证接口契约稳定

​ 在简单单体项目 → 直接用 VO 或实体返回，DTO 可能被合并掉

​ 大型项目/长期维护 → DTO + VO 分得清清楚楚，便于维护、迭代和版本控制

@Data
@Schema(description = "响应结果实体类")
//类级泛型：整个类里所有出现 T 的地方，都必须是同一种类型
//类级 T：整个类通用，若方法不声明 <T>，则方法里用类级的 T
public class Result<T> {

    //返回码
    @Schema(description = "业务状态码")
    private Integer code;

    //返回消息
    @Schema(description = "响应消息")
    private String message;

    //返回数据
    @Schema(description = "业务数据")
    private T data;

    // 私有化构造
    private Result() {}

    // 返回数据
    //第一个<T>：这里表明方法声明了自己的T，只要方法声明了自己的 <T>，方法里的所有 T 都是这个方法的 T，不再使用类的 T
    //不声明的写法public static Result<T> build(T body, Integer code, String message)
    public static <T> Result<T> build(T body, Integer code, String message) {
        //方法级泛型：整个方法里所有出现 T 的地方，都必须是同一种类型
        //方法级 T：只在方法内生效，并覆盖类级 T（若同名）
        Result<T> result = new Result<>();
        result.setData(body);
        result.setCode(code);
        result.setMessage(message);
        return result;
    }

    // 通过枚举构造Result对象
    //教学项目偷懒会写成：public static <T> Result build(T body , ResultCodeEnum resultCodeEnum)
    public static <T> Result<T> build(T body , ResultCodeEnum resultCodeEnum) {
        return build(body , resultCodeEnum.getCode() , resultCodeEnum.getMessage()) ;
    }

}

@Data
public class CustomException extends RuntimeException {
    private Integer code;
    private String msg;
    //这个是必写，在传值的时候有用
    private ResultCodeEnum resultCode;

    public CustomException(ResultCodeEnum resultCode) {
        this.resultCode = resultCode;
        this.code = resultCode.getCode();
        this.msg = resultCode.getMessage();
    }

}

CORS概述

  • CORS的全称为Cross-origin Resource Sharing，中文含义是跨域资源共享
  • CORS 是跨域的一种解决方案，CORS 给了web服务器一种权限：服务器可以选择是否允许跨域请求访问到它们的资源

    }
}

(8)请求从前端到后端的流程

​ 当客户端（前端浏览器、移动端等）发起一个 HTTP 请求时，底层的 Servlet 容器（比如 Tomcat、Jetty、Undertow）会做几件事：

  1. 接收请求报文（比如 URL、Header、Body 等）
  2. 创建 HttpServletRequest 对象 —— 用来封装请求数据
  3. 创建 HttpServletResponse 对象 —— 用来准备回写响应

​ 等同于说

  • HttpServletRequest：Tomcat 解析前端发来的 HTTP 报文（URL、Header、Body 等），并把数据封装到这个对象里。
  • HttpServletResponse：一开始是空对象，提供方法让后端代码写入响应数据，最后由 Tomcat 序列化为 HTTP 响应报文并返回给前端。

(9)拦截器的实现（拦截非登录用户）

实现思路

​ 注意：

​ 1.请求url的判断可以通过拦截规则配置进行实现

​ 2.更新Redis中数据的存活时间的主要目的就是为了保证用户在使用该系统的时候，Redis中会一直保证用户的登录状态，如果用户在30分钟之内没有使用该系统，那么此时登录超时。此时用户就需要重新进行登录

​ 3.将从Redis中获取到的用户存储到ThreadLocal中，这样在一次请求的中就可以在controller、service、mapper中获取用户数据

ThreadLocal

​ ThreadLocal是jdk所提供的一个线程工具类，叫做本地线程变量，意思是ThreadLocal中填充的变量属于当前线程，该变量对其他线程而言是隔离的，也就是说该变量是当前线程独有的变量，使用该工具类可以实现在同一个线程进行数据的共享

具体实现

​ 1.定义LoginAuthInterceptor.java是实现HandlerInterceptor接口，对里面方法preHandle()：请求到达controller前拦截，afterCompletion()：响应返回后。

​ 注意：这里自己构建了一个response返回，正常可以直接抛自定义异常，然后给全局异常处理器返回JSON给前端

​ 优质设计：预检请求（详见10）、滑动过期

@Component
public class LoginAuthInterceptor implements HandlerInterceptor {
    @Autowired
    private RedisTemplate<String,String> redisTemplate;

    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        //获取请求方式-options(预检请求)->直接放行
        //如果不给它放行，走到下面的 token 校验逻辑，因为预检请求本来没带 token → 拦截 → 返回未登录。
        String method = request.getMethod();
        if ("OPTIONS".equals(method)) {
            return true;
        }

        //从请求头获取token，查不到则返回错误提示
        String token = request.getHeader("token");
        if (token == null) {
            responseNoLoginInfo(response);
            return false;
        }

        //从redis里面拿到用户信息
        String s = redisTemplate.opsForValue()
                .get("user:login" + token);
        if (s == null) {
            responseNoLoginInfo(response);
            return false;
        }

        //将用户信息放入threadlocal

        return true;
    }

        //移除threadlocal里的内容
        AuthContextUtil.removeSysUser();
    }

(10)预检请求（operation）

​ 同源请求：没有跨域 → 直接发 → 不存在预检

​ 跨域 + 简单请求：直接发请求，不预检

​ 跨域 + 复杂请求：先预检 (OPTIONS) → 再发真实请求

​ 注意：后端拦截器中，若请求有预检请求且被拦截，后面的请求不会到达

普通请求（简单请求）
  • 不会发预检请求
  • 直接把请求发到后端，浏览器只检查后端返回的 Access-Control-Allow-Origin 等 CORS 响应头。
  • 条件非常苛刻：
    • 方法必须是 GET、HEAD 或 POST
    • POST 的 Content-Type 必须是以下之一：
      • application/x-www-form-urlencoded
      • multipart/form-data
      • text/plain
    • 请求头里不能带自定义 header（比如 Authorization、X-Token）。
特殊请求（复杂请求）
  • 百分百会发预检请求 (OPTIONS)
  • 常见情况：
    • 方法是 PUT、DELETE、PATCH
    • POST 请求用 application/json
    • 请求头里带了 Authorization、X-Token、Content-Type: application/json 等非标准字段

(2)distinct关键字-去重

​ DISTINCT 的作用是 去掉结果集（指定列）里完全重复的行。当三张表，两两直接都是多对多关系时，三表的连接查询结果需要去重

去重效果举例：
SELECT DISTINCT name, age
FROM users;

​ 假设 users 表数据如下：

name age gender
张三 20 男
张三 20 男
李四 22 女
张三 20 女

​ sql执行的结果为：

name age
张三 20
李四 22

​ 解释：

  • 去重的 依据是你查询的列 (name, age)
  • 与 gender 无关，因为你没选它
  • 只要选定列完全相同，就算重复行，会被去掉

7. 前端发送GET和POST请求后端接收处理的区别

​ 底层实际就两种请求：get和post，get是没有请求体，也就是body的，只能在url拼接一些简答的参数。而post将所有参数都放在请求体里面

​ 注意：@RequestBody注解本质，是对json数据进行反序列化，转化为当前数据类型

(1)POST请求-情况一

​ 在使用POST请求以Content-Type:application/json，此时如果后端解析没有 @RequestBody，Spring 就不会去解析 JSON 请求体，如下所示：

//后端
@PostMapping("/findByPage/{pageNum}/{pageSize}")

                                                @PathVariable Integer pageSize,
                                                SysRoleDto sysRoleDto) {
    ...
}
//前端-获得角色列表
export const getSysRoleListByPage = (pageNum,pageSize,queryDto) => {
  return request({
    // ``这个是模板字符串
    url: `${base_api}/findByPage/${pageNum}/${pageSize}`,  //接口路径
    method: 'post',  //提交方式
    //接口@RequestBody 前端使用data:参数名称，表示以JSON传输
    //接口没有用这个注解 前端使用params:参数名称，表示以普通方式传输
    data:  queryDto,
  })

  • 这种请求，参数全在JSON 请求体里，但是你后端方法参数没有加 @RequestBody，所以 SpringMVC 不会去请求体里取值
  • 结果：后端获得的sysRoleDto 是空对象，所有属性 null → 条件查询失效 → 相当于查全部

​ 结论：POST + JSON 必须配合 @RequestBody 才能生效。

        if (!found) {

                    .bucket("spzx-bucket")

        String yyyyMMdd = DateUtil.format(new Date(), "yyyyMMdd");
        String uuid = UUID.randomUUID().toString().replaceAll("-", "");
        String fileName = yyyyMMdd+"/"+uuid+file.getOriginalFilename();

        //文件上传
        minioClient.putObject(PutObjectArgs.builder()
                .bucket("spzx-bucket")
                .stream(file.getInputStream(), file.getSize(), -1)
                .object(fileName)
                .build());

        //获取上传文件在Minio的路径
        String url = "http://192.168.10.129:9001/spzx-bucket/" + fileName;
        return url;
    }

将平铺数据封装为树结构的工具类实现（难、重）

​ 思路：将sysMenuList中每个sysMenu取出，判断父节点等于0，直接当父节点添加到List中（把树的根先构成）。但是因为一颗树又多层，需要一个递归方法getChlid，将id和parentId不等的sysMenu直接返回；从List中找出parentId和当前节点id相等的节点，存入到sysMenu的list节点中，此时因为有多层需要再次递归，实现如下：

//com/rain/spzx/manager/util/BuildTree.java
public class BuildTree {

    public static List<SysMenu> buildTree(List<SysMenu> sysMenuList) {
        List<SysMenu> tree = new ArrayList<SysMenu>();
        for (SysMenu sysMenu : sysMenuList) {
            if (sysMenu.getParentId() == 0) {
                tree.add(getChlid(sysMenu,sysMenuList));
            }
        }
        return tree;
    }

    private static SysMenu getChlid(SysMenu sysMenu, List<SysMenu> sysMenuList) {
    	//为底部建一个list节点
        sysMenu.setChildren(new ArrayList<>());
        for (SysMenu s : sysMenuList) {
            if (sysMenu.getId()==s.getParentId()) {
                sysMenu.getChildren().add(getChlid(s, sysMenuList));
            }
        }
        return sysMenu;
    }
}

private List<SysMenuVo> buildMenus(List<SysMenu> menus) {

    List<SysMenuVo> sysMenuVoList = new LinkedList<SysMenuVo>();
    for (SysMenu sysMenu : menus) {
        SysMenuVo sysMenuVo = new SysMenuVo();
        sysMenuVo.setTitle(sysMenu.getTitle());
        sysMenuVo.setName(sysMenu.getComponent());
        //判断树结构是否有子节点
        List<SysMenu> children = sysMenu.getChildren();
        if (!CollectionUtils.isEmpty(children)) {
        	//使用递归遍历子节点，将子节点放在父节点的children中
            sysMenuVo.setChildren(buildMenus(children));
        }
        将父节点加入到sysMenuVoList中
        sysMenuVoList.add(sysMenuVo);
    }
    return sysMenuVoList;
}

public class ExcelListener<T> implements ReadListener<T> {
    //官网的内容
    /**
     * 每隔5条存储数据库，实际使用中可以100条，然后清理list ，方便内存回收
     */
    private static final int BATCH_COUNT = 100;
    /**
     * 缓存的数据
     */
    private List<T> cachedDataList = ListUtils.newArrayListWithExpectedSize(BATCH_COUNT);

    //这个不由spring注入,通过构造方法传入
    private CategoryMapper categoryMapper;

    public ExcelListener(CategoryMapper categoryMapper) {
        this.categoryMapper = categoryMapper;
    }

    //从Excel里的第二行开始读，把每行读取内容封装到t对象里面
    @Override
    public void invoke(T t, AnalysisContext analysisContext) {
        //通过构造传递mapper，操作数据库
        //把每行数据对象T放到cachedDataList集合里面
        cachedDataList.add(t);
        if (cachedDataList.size() >= BATCH_COUNT) {
            //批量添加到数据库中
            saveData();
            //清理集合
            cachedDataList = ListUtils.newArrayListWithExpectedSize(BATCH_COUNT);
        }
    }


    //所有操作都完成之后执行
    @Override
    public void doAfterAllAnalysed(AnalysisContext analysisContext) {
        saveData();
    }

    private void saveData() {
        categoryMapper.batchInsert((List<CategoryExcelVo>)cachedDataList);
    }
}

15. Controller层-方法返回值详解

​ 在Springboot的项目中，Controller 是对响应体进行封装，Springboot 本质是对响应的封装。如果返回值设置为void，表示Spring 不再帮你生成响应体内容（在使用注解@RequestBody注解时），此时需要你自己手动写入响应体

(1)响应体的格式（4种）

​ 1.返回 JSON 数据（最常见方式）

​ 2.返回视图页面（MVC传统模式）

​ 3.返回 ResponseEntity（我没见过）

​ 4.使用 HttpServletResponse对象手动封装（完全手动）

(2) HttpServletResponse对象手动封装响应体

​ 使用 HttpServletResponse对象获取OutputStream对象（用于手动封装）一共有两种方式

目标 方法 说明
获取输出流对象 response.getOutputStream() 获取二进制输出流对象（用于文件、图片、Excel）
获取字符流对象 response.getWriter() 获取字符输出流对象（用于写字符串或 JSON）
HttpServletResponse对象手动封装响应体实现流程需要的方法
目标 方法 说明
获取输出流对象 response.getOutputStream() 获取 二进制输出流对象（ServletOutputStream），用于写入文件、图片、Excel 等二进制内容
写入响应体（二进制） out.write(byte[] b) 向响应体中写入字节数据（最常用）
out.write(byte[] b, int off, int len) 从字节数组中指定位置开始写入指定长度的数据
out.flush() 将缓冲区的内容立即发送到客户端（强制刷新）
out.close() 关闭输出流（释放资源）
获取字符流对象 response.getWriter() 获取 字符输出流对象（PrintWriter），用于输出字符串、HTML 或 JSON 文本内容
写入响应体（文本） writer.write(String s) 写入字符串到响应体（常用于 JSON 或普通文本）
writer.println(String s) 写入字符串并换行（相当于 write(s + "\n")）
writer.flush() 刷新缓冲区，把内容立即发送到客户端
writer.close() 关闭字符流（释放资源）

(3)HttpServletRequest对象和HttpServletResponse对象的理解

​ 后端通过 输入流（InputStream） 从前端发送的 HTTP 协议 body 中读取数据，后端对前端的响应通过 输出流（OutputStream） 将数据写入到 HTTP 协议 body 中。其中，输入流 InputStream 被封装在 HttpServletRequest 对象中，输出流 OutputStream 被封装在 HttpServletResponse 对象中

@Aspect

    //拦截所有方法上标了 @Log 注解的方法，里面写全限定名
    @Around(value = "@annotation(com.rain.spzx.common.log.annotation.Log)")
    public Object doAroundAdvice(ProceedingJoinPoint pjp) {
    	//只有子类下有方法getMethod()，所以必须强转
        MethodSignature signature = (MethodSignature)pjp.getSignature();
        Method method = signature.getMethod();
        //该注解写在方法上，所以应该用方法拿
        //注意引入Log别引入到hutool包下的Log了
        Log log = method.getAnnotation(Log.class);
        //获取模块名称
        String title = log.title();
        //获取操作人类别
        OperatorType operatorType = log.operatorType();
        System.out.println("title:" + title +",operatorType:" + operatorType);

        Object proceed = null;
        try {
            proceed = pjp.proceed();
            System.out.println("在业务方法之后执行");
        } catch (Throwable e) {
            throw new RuntimeException(e);
        }
        return proceed;
    }
}

                                       SysOperLog sysOperLog) {

        // 设置操作模块名称
        sysOperLog.setTitle(sysLog.title());
        sysOperLog.setOperatorType(sysLog.operatorType().name());

        // 获取目标方法信息
        MethodSignature methodSignature = (MethodSignature) joinPoint.getSignature() ;
        Method method = methodSignature.getMethod();
        sysOperLog.setMethod(method.getDeclaringClass().getName());

        // 获取请求相关参数
        ServletRequestAttributes requestAttributes = (ServletRequestAttributes)
                RequestContextHolder.getRequestAttributes();
        HttpServletRequest request = requestAttributes.getRequest();
        sysOperLog.setRequestMethod(request.getMethod());
        sysOperLog.setOperUrl(request.getRequestURI());
        sysOperLog.setOperIp(request.getRemoteAddr());

        // 设置请求参数
        if(sysLog.isSaveRequestData()) {
            String requestMethod = sysOperLog.getRequestMethod();
            if (HttpMethod.PUT.name().equals(requestMethod) || HttpMethod.POST.name().equals(requestMethod)) {
                String params = Arrays.toString(joinPoint.getArgs());
                sysOperLog.setOperParam(params);
            }
        }
        sysOperLog.setOperName(AuthContextUtil.getSysUser().getUserName());
    }

    public Object doAroundAdvice(ProceedingJoinPoint pjp) {
        //拿到Log对象
        MethodSignature signature = (MethodSignature)pjp.getSignature();
        Method method = signature.getMethod();
        Log log = method.getAnnotation(Log.class);

        SysOperLog sysOperLog = new SysOperLog();
        LogUtil.beforeHandleLog(log,pjp,sysOperLog);

        Object proceed = null;
        try {
            proceed = pjp.proceed();
            LogUtil.afterHandlLog(log,proceed,sysOperLog,0,null);
        } catch (Throwable e) {
            LogUtil.afterHandlLog(log,proceed,sysOperLog,1,e.getMessage());
            //如果使用事务，则必须抛出异常，否则事务不会回滚，事务也是AOP实现，且优先级最高
            throw new RuntimeException();
        }

        //将日志信息存入数据库
        asyncOperLogService.saveSysOperLog(sysOperLog);

        return proceed;
    }
}

(2) 展示所有分类（3层，树状显示）

实现思路

​ 1.先把所有分类以一个list查询出来

​ 2.对这个list重新组装。先查第一层数据（id=0），获得一个新集合-One；再遍历One，遍历出每个元素-item，在循环中，用stream流将list重新过滤，过滤出的单个元素的parentId与item中的id比较，相等的组成一个新集合-two，将two放入item中的child节点。基于One的遍历循环中，重复流程对two的遍历与list遍历元素对比，等到新集合three，最后将thee放到two的遍历的元素的child节点（由此3层数据封装完毕）

//组成树的核心算法实现
public List<Category> findCategoryTree() {
    // 1.查询全部的list
    List<Category> list = categoryMapper.selectAll();

    // 2.遍历全部的list，组装成树
    //获得一级分类
    List<Category> OneCategoryList = list.stream()
            .filter(e -> e.getParentId()
                    .longValue() == 0)
            .collect(Collectors.toList());
    //一级分类组装二级分类
    OneCategoryList.forEach(oneCategory -> {
        List<Category> twoCategoryList = list.stream()
                .filter(item -> item.getParentId() == oneCategory.getId())
                .collect(Collectors.toList());
        oneCategory.setChildren(twoCategoryList);

        //二级分类组装三级分类
        twoCategoryList.forEach(twoCategory -> {
            List<Category> threeCategoryList = list.stream()
                    .filter(item -> item.getParentId() == twoCategory.getId())
                    .collect(Collectors.toList());
            twoCategory.setChildren(threeCategoryList);
        });
    });
    return OneCategoryList;
}

(3) Spring Cache

​ Spring Cache是一个框架，实现了基于注解的缓存功能，只需要简单地加一个注解，就能实现缓存功能，大大简化我们在业务中操作缓存的代码

​ Spring Cache只是提供了一层抽象，底层可以切换不同的cache实现。具体就是通过CacheManager接口来统一不同的缓存技术。CacheManager是Spring提供的各种缓存技术抽象接口

不同的缓存技术需要实现不同的CacheManager
CacheManager 描述
EhCacheCacheManager 使用EhCache作为缓存技术
GuavaCacheManager 使用Google的GuavaCache作为缓存技术
RedisCacheManager 使用Redis作为缓存技术

​ 在spring boot项目中，使用缓存技术只需在项目中导入相关缓存技术的依赖包，并在启动类上使用@EnableCaching开启缓存支持即可。使用Redis作为缓存技术，只需要导入Spring data Redis的maven坐标

SpringCache提供的常用的缓存操作的注解
注解 位置 说明
@EnableCaching 类上 全局开关，用于开启缓存注解功能（一般加在启动类或配置类上）
@Cacheable 方法上 在方法执行前先查缓存，有则直接返回；无则执行方法并缓存结果
@CachePut 方法上 执行方法，并将方法返回值放入缓存（不会跳过方法执行）
@CacheEvict 方法上 删除缓存中的一条或多条数据
注解：@Cacheable（查询方法使用）

​ 写在方法上，作用：spring先查看缓存中是否有数据，如果有数据，则直接返回缓存数据；若没有数据，调用方法并将方法返回值放到缓存中

​ value：表示缓存的命名空间（缓存分组名称），自定义名字

​ key：用于唯一标识一条缓存数据的键，一般**#形参名（非对象）**或#形参名.属性名（对象）

​ 注意：在有缓存的情况下会跳过方法执行

//存入redis的key为 userCache::形参Id

​ 思路：只对路径（/* */auth/**）进行拦截，如果登录则放行，否则拦截。其余路径正常放行

//com/rain/spzx/gateway/filter/AuthGlobalFilter.java
@Component
public class AuthGlobalFilter implements GlobalFilter , Ordered {

    @Autowired
    private RedisTemplate<String,String> redisTemplate;

    //用于匹配一类规则的路径
    private AntPathMatcher antPathMatcher = new AntPathMatcher();

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        //获取请求路径
        ServerHttpRequest request = exchange.getRequest();
        String path = request.getURI()
                .getPath();

        //判断路径是否满足规则：/api/**/auth/**，满足进行校验
        if (antPathMatcher.match("/api/**/auth/**", path)) {
            //登录校验
            String token = request.getHeaders().getFirst("token");
            if (StringUtils.hasText(token)) {
                String tokenRedis = redisTemplate.opsForValue()
                        .get(token);
                if (tokenRedis != null) {
                    UserInfo userInfo = JSON.parseObject(tokenRedis, UserInfo.class);

                    if (userInfo!=null){
                        //用户处于登录状态-放行
                        return chain.filter(exchange);
                    }


                }
            }

            //组装响应体-返回错误信息
            Result result = Result.build(null, ResultCodeEnum.LOGIN_AUTH);
            //HTTP响应底层只能传“字节流”，不能直接传对象或字符串
            byte[] bytes = JSONObject.toJSONString(result)
                    .getBytes(StandardCharsets.UTF_8);
            ServerHttpResponse response = exchange.getResponse();
            DataBuffer wrap = response.bufferFactory()
                    .wrap(bytes);
            //指定编码
            response.getHeaders().add("Content-Type", "application/json;charset=UTF-8");
            return response.writeWith(Mono.just(wrap));

        }

        //非要拦截请求-放行
        return chain.filter(exchange);

    }

    @Override
    public int getOrder() {
        return 0;
    }
}

业务问题与解决

​ 当前购物车查询用的是用户Id，但是实际上是获取不到的。因为链条实际上应该是如下所示，当前业务代码缺乏拦截器RequestInterceptor

​ 注意：微服务之间的调用不走网关，只有外部请求会走网关。但微服务之间的调用会走拦截器

请求A -> Gateway网关 -> A服务HandlerInterceptor解析token（HTTP请求进入服务时执行），根据token查询Redis， 将UserInfo放入A服务ThreadLocal -> Controller业务处理 -> Feign远程调用（此时不会自动携带A的ThreadLocal） -> 请求A的Feign RequestInterceptor（拦截Feign即将发出的请求）执行，从请求AHeader获取token， 将token添加到Feign新请求Header -> 正式发送HTTP请求B

B服务收到请求 -> B服务HandlerInterceptor解析token ，根据token查询Redis ，将UserInfo放入B服务自己的ThreadLocal -> B业务处理 -> 返回Feign结果 -> A返回最终结果

具体实现4-编写拦截器RequestInterceptor

//com/rain/spzx/common/feign/UserTokenFeignInterceptor.java
public class UserTokenFeignInterceptor implements RequestInterceptor {
    @Override
    public void apply(RequestTemplate requestTemplate) {
        //从当前线程中拿到原来的HTTP请求
        ServletRequestAttributes requestAttributes = (ServletRequestAttributes)RequestContextHolder.getRequestAttributes();
        HttpServletRequest request = requestAttributes.getRequest();
        String token = request.getHeader("token");
        //给Feign即将发送的新HTTP请求添加请求头
        requestTemplate.header("token", token);
    }
}

public Long submitOrder(OrderInfoDto orderInfoDto) {
    List<OrderItem> orderItemList = orderInfoDto.getOrderItemList();
    //空订单校验
    if(CollectionUtils.isEmpty(orderItemList)){
        throw new CustomException(ResultCodeEnum.DATA_ERROR);
    }

    //校验库存是否充足-对每个订单项进行校验
    orderItemList.forEach(item -> {
        //skuId用于查库存
        Long skuId = item.getSkuId();
        //需要的商品数量
        Integer skuNum = item.getSkuNum();
        //远程调用进行比对
        ProductSku productSku = productFeignClient.getProductSku(skuId);
        if (productSku == null) {
            throw new CustomException(ResultCodeEnum.DATA_ERROR);
        }
        if (skuNum > productSku.getStockNum()) {
            throw new CustomException(ResultCodeEnum.STOCK_LESS);
        }
    });

    //远程调用：根据获取地址信息
    Long userAddressId = orderInfoDto.getUserAddressId();
    System.out.println(userAddressId);
    UserAddress userAddress = userFeignClient.getUserAddress(userAddressId);

    //获取用户信息
    UserInfo userInfo = AuthContextUtil.getUserInfo();

    //计算总金额
    BigDecimal totalPrice = new BigDecimal(0);
    for (OrderItem orderItem : orderItemList) {
        totalPrice = totalPrice.add(orderItem.getSkuPrice().multiply(BigDecimal.valueOf(orderItem.getSkuNum())));
    }

    //构建订单
    OrderInfo orderInfo = new OrderInfo();
    //订单编号-给外人看的，内部用id，外部用编号
    orderInfo.setOrderNo(String.valueOf(System.currentTimeMillis()));
    //用户id
    orderInfo.setUserId(userInfo.getId());
    //用户昵称
    orderInfo.setNickName(userInfo.getNickName());
    //地址相关
    orderInfo.setReceiverName(userAddress.getName());
    orderInfo.setReceiverPhone(userAddress.getPhone());
    orderInfo.setReceiverTagName(userAddress.getTagName());
    orderInfo.setReceiverProvince(userAddress.getProvinceCode());
    orderInfo.setReceiverCity(userAddress.getCityCode());
    orderInfo.setReceiverDistrict(userAddress.getDistrictCode());
    orderInfo.setReceiverAddress(userAddress.getFullAddress());
    //金额与其他
    orderInfo.setTotalAmount(totalPrice);
    orderInfo.setCouponAmount(new BigDecimal(0));
    orderInfo.setOriginalTotalAmount(totalPrice);
    orderInfo.setFeightFee(orderInfoDto.getFeightFee());
    orderInfo.setPayType(2);
    orderInfo.setOrderStatus(0);

    //保存到数据库orderInfo表
    orderInfoMapper.save(orderInfo);

    //保存订单项信息到订单项表
    for (OrderItem orderItem : orderItemList) {
        //将订单id设置在每个订单项
        orderItem.setOrderId(orderInfo.getId());
        orderItemMapper.save(orderItem);
    }

    //组装日志信息
    OrderLog orderLog = new OrderLog();
    orderLog.setOrderId(orderInfo.getId());
    orderLog.setProcessStatus(0);
    orderLog.setNote("提交订单");

    //保存信息到日志表
    orderLogMapper.save(orderLog);

    //远程调用，清空购物车
    cartFeignClient.deleteChecked();

    return orderInfo.getId();
}

项目与支付宝请求的处理流程
  1. 首先，由项目封装支付宝的alipayRequest，使用alipayClient发送请求给支付宝，response = alipayClient.pageExecute(alipayRequest);
  2. 此时，返回的response ，是支付宝的同步回调（包含：支付码、用户可以登录并支付、支付宝支付成功的页面），最后返回到你指定的跳转页面return_payment_url（这步，就算你不放公网，也是能正常执行的）
  3. 然后，扫码支付，支付宝在确认收款后，会请求你指定的接口notify_payment_url（该路径必须在公网上可发现），支付宝会返回支付成功的签名，你再验证签名是否有效。然后你可以编写支付成功后的业务逻辑（订单状态的更改、库存的删减）

public PaymentInfo savePaymentInfo(String orderNo) {

    PaymentInfo paymentInfo = paymentInfoMapper.selectByOrderNo(orderNo);

        String content = "";

        paymentInfo.setContent(content);
        paymentInfo.setAmount(orderInfo.getTotalAmount());
        paymentInfo.setOrderNo(orderNo);
        paymentInfo.setPaymentStatus(0);

        paymentInfoMapper.save(paymentInfo);
    }
    return paymentInfo;
}

//AlipayServiceImpl.java
public String submitAlipay(String orderNo) {
    //保存支付信息-这个具体实现看(3)
    PaymentInfo paymentInfo = paymentInfoService.savePaymentInfo(orderNo);

    //创建Alipay API对应的request
    AlipayTradeWapPayRequest alipayRequest = new AlipayTradeWapPayRequest();

    // 同步回调：本方法直接
    alipayRequest.setReturnUrl(alipayProperties.getReturnPaymentUrl());

    // 异步回调：等待用户支付完成后，支付宝服务对我们服务发送的请求
    alipayRequest.setNotifyUrl(alipayProperties.getNotifyPaymentUrl());

    // 准备请求参数 ，声明一个map 集合
    HashMap<String, Object> map = new HashMap<>();
    map.put("out_trade_no",paymentInfo.getOrderNo());
    map.put("product_code","QUICK_WAP_WAY");
    //获取总额
    map.put("total_amount",paymentInfo.getAmount());
    map.put("subject",paymentInfo.getContent());
    alipayRequest.setBizContent(JSON.toJSONString(map));

    // 向支付宝发送请求
    AlipayTradeWapPayResponse response = null;
    try {
        response = alipayClient.pageExecute(alipayRequest);
    } catch (AlipayApiException e) {
        throw new RuntimeException(e);
    }
    if (response.isSuccess()) {
        return response.getBody();
    }else {
        throw new CustomException(ResultCodeEnum.DATA_ERROR);
    }
}

//接收支付宝异步发送用户支付成功的接口
//注意：支付宝发送的请求不包含token，所以以下路径，包括业务中的远程调用，都需要在拦截器处声明不拦截
@RequestMapping("/callback/notify")
public String alipayNotify(@RequestParam Map<String, String> paramMap, HttpServletRequest request){
    System.out.println("支付成功，支付宝成功回调");

    //验证签名
    boolean signVerified = false; //调用SDK验证签名
    try {
        signVerified = AlipaySignature.rsaCheckV1(paramMap, alipayProperties.getAlipayPublicKey(), AlipayProperties.charset, AlipayProperties.sign_type);
    } catch (AlipayApiException e) {
        e.printStackTrace();
    }

    // 交易状态
    String trade_status = paramMap.get("trade_status");

    if (signVerified) {
        //支付成功
        //验签成功后，按照支付结果异步通知中的描述，对支付结果中的业务内容进行二次校验，校验成功后在response中返回success并继续商户自身业务处理，校验失败返回failure
        if ("TRADE_SUCCESS".equals(trade_status) || "TRADE_FINISHED".equals(trade_status)) {
            // 正常的支付成功，更新交易记录状态、删减库存等操作
            paymentInfoService.updatePaymentStatus(paramMap,2);
            return "success";
        }

        return "failure";
    }else {
        return "failure";
    }
}


//PaymentInfoServiceImpl.java
public void updatePaymentStatus(Map<String, String> paramMap, int payType) {
    //从支付宝的返回map中拿到订单号，并查询对应的订单
    PaymentInfo paymentInfo = paymentInfoMapper.selectByOrderNo(paramMap.get("out_trade_no"));

    //如果订单已支付，直接返回
    if (paymentInfo.getPaymentStatus() == 1) {
        return;
    }

    //否则更新订单
    paymentInfo.setPaymentStatus(1);
    paymentInfo.setOutTradeNo(paramMap.get("trade_no"));
    paymentInfo.setCallbackTime(new Date());
    paymentInfo.setCallbackContent(JSON.toJSONString(paramMap));
    paymentInfoMapper.update(paymentInfo);

    //远程调用：更新订单支付状态
    orderFeignClient.updateOrderStatusPayed(paymentInfo.getOrderNo(), payType);

    //远程调用*2：更新库存数量(增加销量，减少库存值)
    OrderInfo orderInfo = orderFeignClient.getOrderInfoByOrderNo(paymentInfo.getOrderNo());
    List<SkuSaleDto> skuSaleDtoList = orderInfo.getOrderItemList()
            .stream().map(item ->{
                SkuSaleDto skuSaleDto = new SkuSaleDto();
                skuSaleDto.setSkuId(item.getSkuId());
                skuSaleDto.setNum(item.getSkuNum());
                return skuSaleDto;
            }).collect(Collectors.toList());
    productFeignClient.updateSkuSaleNum(skuSaleDtoList) ;
}
